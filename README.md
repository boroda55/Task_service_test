# Task Service

Асинхронный сервис для управления и фоновой обработки задач.
Реализован на FastAPI с использованием RabbitMQ для очереди сообщений и PostgreSQL для хранения данных.

## Стек технологий

- Python 3.11
- FastAPI, SQLAlchemy 2.0 (async), Alembic
- PostgreSQL 14, RabbitMQ, aio-pika
- Pytest, httpx (для интеграционных тестов)

## Запуск проекта

1. Скопируйте файл с переменными окружения:
   ```bash
   cp .env.example .env
   ```

2. Запустите сервисы через Docker Compose:
   ```bash
   docker-compose up --build
   ```

3. Документация API (Swagger) будет доступна по адресу:
   http://localhost:8000/docs

## Тестирование

Тесты используют in-memory SQLite для изоляции и быстродействия.
Это обеспечивает мгновенный feedback loop и не требует поднимать реальный PostgreSQL.
Если нужен запуск тестов строго на PostgreSQL, архитектура позволяет переключить конфигурацию на testcontainers.

```bash
# Запуск всех тестов
pytest -v

# Запуск с отчетом о покрытии
pytest --cov=app --cov-report=term-missing
```

## Архитектурные решения

- **Разделение ответственности**: Использован паттерн Service/Repository. Репозиторий отвечает только за CRUD, бизнес-логика и управление транзакциями находятся в сервисе.
- **Параллельная обработка**: Воркер настроен с `prefetch_count=10`, что позволяет обрабатывать несколько задач одновременно без блокировки.
- **Отказоустойчивость**: При возникновении исключения во время обработки сообщение возвращается в очередь (`requeue=True`). Реализованы повторные попытки через `tenacity` (3 попытки с экспоненциальной задержкой). Статус задачи меняется на `FAILED` с сохранением текста ошибки.
- **Идемпотентность**: Воркер проверяет статус задачи перед началом обработки, игнорируя дубликаты сообщений из очереди (Idempotency guard).
- **Работа со временем**: Во всем проекте используются timezone-aware объекты (`datetime.now(timezone.utc)`).
- **Управление схемой БД**: Создание и изменение таблиц выполняется исключительно через Alembic миграции, `create_all` не используется.

## API Endpoints

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/v1/tasks` | Создание новой задачи |
| GET | `/api/v1/tasks` | Список задач (параметры: `status`, `priority`, `page`, `per_page`) |
| GET | `/api/v1/tasks/{task_id}` | Детальная информация о задаче |
| GET | `/api/v1/tasks/{task_id}/status` | Получение текущего статуса задачи |
| DELETE | `/api/v1/tasks/{task_id}` | Отмена задачи (перевод в статус CANCELLED) |
| GET | `/health` | Health check для мониторинга |
